# Lessons

Mistakes already made once, one line each, dated. Read the lines that match your task; delete a line once a check enforces it.

- **A closed fd lives on in a concurrent spawn** (2026-10-12). A child mid-posix_spawn holds every parent fd until exec; a just-closed listener accepted 706/3000 connects beside spawning threads. *Apply:* in a process that spawns concurrently, never assert "gone" right after a close. Make the stub server unable to accept at all (bind a stale socket without `listen`), or poll for the outcome with a deadline. Probe a race in the window it lives in: assert from the parent during the spawn, not from the child after exec.
- **A comment outlives the bug it describes** (2026-11-16). A comment saying "this is a live bug, not fixed here" goes stale silently when you fix it — nothing tests comments, and the next reader believes it. *Apply:* such a write-off comment breaks the no-comments rule in code-quality: put it in the PR body or a ticket instead. When you meet an old one, the moment you fix something you had written off, grep your own diff for the write-off before pushing (`git diff origin/main... | grep -nE "live bug|not fixed here|belongs in|for now"`).
- **A comparative comments numbers belong to the rejected design** (2026-09-01). A comment contrasting "we do X rather than Y, which cost N" attaches N to Y; quoted later it becomes the cost of X. *Apply:* when a comment's figure is load-bearing for a decision, find the verb it attaches to before using it, and check the code underneath actually still does the expensive thing. Here two more reads killed the theory outright: the generator runs on a `Task.detached` so it cannot hold the main actor at any speed.
- **A fresh asdf node has no yarn** (2026-10-07). A Node version just installed with asdf has no yarn until corepack is enabled in it; every yarn step exits 126 with "No version is set for command yarn", which reads like a project failure. *Apply:* after installing a Node version for a Yarn repo, run `ASDF_NODEJS_VERSION=<v> corepack enable && asdf reshim nodejs <v>`, then check `yarn --version` under it before trusting any run. CI does the same with its `corepack enable` step.
- **A margin can empty its window** (2026-10-10). A cost that pads a target window inward by a fixed margin never reaches 0 on a window narrower than two margins, so staged search never runs the stages behind it. *Apply:* when a staged search keeps missing one stage, first log each restart's final cost. The same nonzero value on every restart means a floor the search can't get under, not bad luck. Check every window against `width > 2 × margin` and the measure's granularity (k/40).
- **A pipe swallows the exit code** (2026-09-01). A pipeline's exit status is its last command's: `swift test | grep` reports grep's, so a killed suite reads as a pass, and `git commit | tail && git reset` runs the reset even when the commit failed. *Apply:* never pipe a command whose result you report or whose failure should stop the chain; capture its exit code first (`out=$(cmd); rc=$?`) and branch on that. When reading a run's log, **count the suites, not the failures**: a process killed part-way through prints `0 failures` for everything it managed to run, which is indistinguishable from a pass unless you notice only 6 of ~100 suites appeared.
- **A rebuild looks exactly like a stall** (2026-08-30). CPU stats can't tell a build phase from a serial run, and dying stragglers share the process name — check the phase before diagnosing slowness. *Apply:* before diagnosing slowness from process stats, establish which *phase* the process is in — look for the work's own output marker, not CPU percentage. Match the pid explicitly rather than taking the first row, and check whether a restart happened before reading elapsed time as continuity.
- **A row crossing foreach blocks renders stale** (2026-10-13). In a LazyVStack, an item that moves from one ForEach to another kept its old rendering; one ForEach over an enum of rows fixes it. *Apply:* render a list whose items change groups from a single `ForEach` over an enum (rows, headers, notes), so a change of group is a move within one collection, and drop per-row `.id()` that duplicates the ForEach id. Verify any group change with a capture after the transition, not before.
- **A script resolves node_modules from its own folder** (2026-06-12). Node resolves `node_modules` from the script's folder, not the cwd, so a Playwright runner script kept outside the worktree loads another tree's packages or none. *Apply:* put a loop's runner script inside the worktree it drives.
- **A search guard must not demand the destination** (2026-08-31). A guard that asks every intermediate step for the property only the final answer must have freezes the search; it looks like a hard problem, not a broken gate. *Apply:* ask the destination property of the **returned** result only, and ask each step for the weaker thing that keeps the destination *reachable* — "the other measure still reads something", not "the same value". Nil is a third case, not a value to compare: `guard let x else { allow }`.
- **A waiter must die with its start** (2026-10-22). A wait loop chained after a start that failed waits forever; make every step exit on failure and cap the wait. *Apply:* in any start-then-wait script, end on each failed step (`|| { echo why; exit 1; }`), cap the wait with a deadline that prints, and give each run a unique token in its done-marker. Before adding a second waiter, check the thing being waited on is alive.
- **A write to a dead childs stdin kills the parent** (2026-10-12). Writing to a Foundation Process's stdin Pipe after the child exits raises SIGPIPE and kills the whole app or test runner (signal 13); set F_SETNOSIGPIPE on the write end. *Apply:* any Swift code that keeps a child's stdin open (a JSON-RPC client, an interactive tool) sets F_SETNOSIGPIPE before its first write. Prove it with a loop that writes after the child's exit event.
- **An error takes the shape of what you expect** (2026-08-31). The same failure read as "main is broken" to one person and "the build is fast" to another; an ambiguous result confirms whichever hypothesis you brought to it. *Apply:* when a result confirms what you expected, ask what **else** would produce it before acting. Cheap discriminators: does the timing make sense for the work claimed (7.86s is not a release compile of this package); did the step that was supposed to do the work actually report doing it; would this same output appear if my hypothesis were false?
- **Arrival is date added not modified** (2026-10-12). A copied or moved file keeps its old modification date; "when did this arrive" is URLResourceKey.addedToDirectoryDateKey (Finder's Date Added). *Apply:* for any "recent files", "what's new" or inbox feature, use Date Added and fall back to mtime only where the volume doesn't keep it. A loop can't backdate Date Added, so backdate mtime in its made-up data and check that the file still counts as new.
- **Asc api key cannot cloud sign** (2026-10-16). xcodebuild -exportArchive with the ASC API key fails 'Cloud signing permission error / No profiles'; the same export through Xcode's signed-in account uploads fine. *Apply:* run the same export with `-allowProvisioningUpdates` and no `-authentication*` flags, so xcodebuild uses the Apple ID signed into Xcode; it cloud-signs and uploads. Don't create or revoke distribution certificates to work around it: other machines' signing keychains may depend on the existing ones.
- **Bsd tr locale dependent slug** (2026-08-07). BSD tr -c 'A-Za-z0-9' '_' on macOS splits multibyte chars differently depending on the shell's ambient locale — pin LC_ALL=C when sanitizing free-form names into stable slugs/paths/identifiers.
- **Cleanup belongs in a trap** (2026-09-01). Cleanup written after the work only runs if the work finishes; a timeout skips it and leaves load on a shared box. *Apply:* set a `trap 'kill "${PIDS[@]}" 2>/dev/null' EXIT INT TERM` before starting anything, not after. Capture exact PIDs and kill those — never `pkill` by name on a shared box, which has already killed other agents' test runs. Then verify: `ps -eo pid,pcpu,command` and confirm nothing of yours survived, because assuming the process group died is the same class of error as assuming the cleanup ran.
- **Completed count lies during item one** (2026-08-30). A "has started" flag derived from completed items reads false for the whole of the first item. *Apply:* when a view model exposes `isStarted` / `isComplete` / `nextItem`, check what each is derived from and whether work in progress has produced any evidence yet. If it has not, carry the in-progress evidence explicitly and make the parameter non-defaulted so a caller cannot silently read zero.
- **Conjunct predicate hides its own narrowing** (2026-08-15). A scanner built as A && B && C is limited by its narrowest clause, and reading it never reveals that — relax each anchor in turn and diff the flagged lists.
- **Contrast check both axes** (2026-08-01). A filled button has TWO contrast axes — label-on-fill and fill-on-surface. Check both, every time; I keep naming the wrong one. *Apply:* when a fill changes, compute both numbers in both themes before shipping — four figures, not one. Composite translucent fills against their real backdrop first (`rgba` over a gradient is not the colour you typed). And write the assertion, because both failure modes are silent: the button still renders, it is just unreadable or edgeless.
- **Docs prose rot vs path rot** (2026-08-07). Machine-checkable doc verification (links, paths, counts, exports) is STRUCTURALLY BLIND to the worst doc defects. The dangerous ones are prose that is wrong about behaviour — and a doc that annotates its own staleness reads as maintained while being wrong.
- **Env knob arithmetic injection** (2026-08-01). A shell env var used in bash arithmetic (( x < var )) is a command-injection boundary — bash evaluates a[$(cmd)] as CODE there. Verified executing. Adding a knob to a script that validates its knobs means validating yours too.
- **Fix to shared helper misses inlined callers** (2026-08-05). When a fix to a shared helper changes nothing, check the failing path actually calls it — one call site had inlined its own copy. *Apply:* before patching a shared helper to fix a specific failure, prove the failing path reaches it. Grep for what the helper *does* (`JSON.parse`, `fetch(`, the raw operation) across the module, not just for the helper's *name* — inlined duplicates are invisible to a name grep.
- **Fix wired into one hop of several** (2026-08-19). A cross-cutting header fix wired into ONE of several internal hops reads as complete and is not — count the hops before declaring it fixed. *Apply:* when a fix introduces a header that must cross an internal boundary, grep its call sites and enumerate every hop that must carry it *before* calling it fixed. Collapse the readers to ONE definition and pin that the hops agree, so they cannot drift.
- **Fixed size text in a flexible pane lifts the window** (2026-10-13). .fixedSize(horizontal: false, vertical: true) text in a flexible-width SwiftUI pane sets the window's minimum height and pushes all content up out of the window. *Apply:* in any flexible-width pane, use `.lineLimit(n)` instead of the fixed-size idiom. When a whole Mac window renders shifted up with idle CPU, check for fixed-size text first.
- **Forward the truth, never re-derive it** (2026-08). When a view or fixture shows an untrue value, delete its ability to compute the value and forward from the one component that owns it; correcting the formula leaves the surface that made the lie. *Apply:* build fixtures, samples and loop seed data through the real types and state machine, so they can only express reachable states.
- **Git grep e knows no backslash classes** (2026-10-05). POSIX ERE has no `\b` or `\s`, so on macOS `git grep -E 'name\b'` silently matches nothing and `^\s*(it|test)\(` degrades to `^s*`, matching only column-0 lines; a zero-hit search read as "unused" twice in one session. *Apply:* for word matches in git grep, use `-w` or `-P`, and for whitespace `[[:space:]]`. Before an "unused" or "not referenced" conclusion, run the same search on a token you know is present (a control).
- **Grep the identifier the code uses** (2026-08-15). Twice in one session I concluded 'nothing else references this' from a grep that searched the WRONG identifier — Prisma's camelCase accessor misses raw-SQL table names, and a literal column name misses columns reached through a mapping.
- **Grep the render not the rule importers** (2026-08-22). A shared display rule looks fully adopted when you grep its helper; grep the RENDER instead — the surfaces missing from the hits are often the ones whose DTO cannot even reach the rule. *Apply:* grep the *render* (`toFixed(1)`, `String(format: "%.1f")`, the numeral), subtract the set importing the rule, and investigate the difference. Then cross-check each for a legitimate exemption before calling it a bug.
- **Hidden tab omits intersection lazy content** (2026-08-20). A browser-driven design review through a hidden tab silently omits every intersection-lazy element — screenshots still look right, so it reads as a product bug. *Apply:* 1. Before concluding anything from a browser-driven visual review, assert the page is actually rendering: `document.visibilityState === "visible"` and a `requestAnimationFrame` callback fires. If not, nothing lazy is trustworthy. 2. `resize_window` reported success while the captured viewport stayed 1316×908 — verify a resize took effect by reading `innerWidth`, don't trust the tool's "Successfully resized".
- **Jq fromdateiso8601 aborts on fractional seconds** (2026-08-09). jq's fromdateiso8601 accepts ONLY `%Y-%m-%dT%H:%M:%SZ` and HARD-ERRORS on fractional seconds — aborting the whole filter mid-stream after emitting a partial list. In a delete loop that means a partial sweep, not a clean skip.
- **Listing a folder resolves its symlinks** (2026-10-21). FileManager.contentsOfDirectory(at:) returns /private/var/... for a /var/... folder, so path-equality checks on temp dirs fail. *Apply:* when the app or a loop compares paths from a directory listing as strings, use the caller's folder path. Don't resolve the made-up data to match the listing.
- **Ncu misses prereleases and overrides** (2026-08-05). "Update all to latest" via npm-check-updates silently skips prerelease-pinned deps and never touches the overrides/resolutions block — where the worst CVEs hide. *Apply:* after any update-to-latest pass, audit a saved copy of the pre-update manifest and lockfile too and diff the two audits (Yarn 1 counts *paths*, not packages, so its number is not comparable to Dependabot's). Raise each remaining override or resolution floor to the advisory's `patched_versions` and check the installed version actually moved, and check any `-beta` or `-rc` pin by hand.
- **One idle process is not the platform** (2026-09-01). Three times I measured one process on an idle machine and wrote it down as a property of the renderer; say machine, configuration and process count beside every number. *Apply:* state the machine, the configuration and the process count next to any number you record. Prefer the ratio or the mechanism over the absolute figure, since those travel and milliseconds do not. And when a limit is real but local — contention that only a multi-worktree dev box produces, never CI's one-job-per-machine — say where it does *not* apply, or the caveat rots into folklore.
- **Partial styles migration manufactures drift** (2026-08-01). Migrating one export from a styles module and leaving its siblings creates the inconsistency the migration was meant to remove — enumerate every export. *Apply:* - `grep -n "^export" <styles-file>` before starting, and account for every line at the end. - After deploying a visual change, look at the deployed page. Three separate defects on this branch were found that way and by nothing else: an inert scroll-snap, an inert `:hover`, and this.
- **Pgrep f matches the waiting shell** (2026-08-30). A wait-loop using `pgrep -f "name"` matches its own command line, so it never exits; use `pgrep -x`. *Apply:* use `pgrep -x <exact-process-name>` for a wait condition — it matches the process *name* only and cannot match a shell. Reserve `pgrep -f` for one-shot inspection where you can eyeball the matches. When a waiter seems stuck, check with `ps -eo pid,etime,%cpu,comm | grep "/toolname"` before believing it: a real process shows CPU and a growing elapsed time, and a self-match shows a shell.
- **Pillow rgba getbbox reads alpha only** (2026-10-12). Pillow's getbbox() on an RGBA ImageChops.difference reads ALPHA only, so two opaque snapshots that differ report bbox None ("identical"); convert to RGB first. *Apply:* when diffing snapshot PNGs, do `.convert("RGB")` before `ImageChops.difference`, or call `getbbox(alpha_only=False)`. Also count the changed pixels, not just the bbox. If the diff says "no change" after a change you expected to be visible, distrust the diff before you distrust the change.
- **Ps elapsed is age not load** (2026-10-12). ps %CPU is a moment and ELAPSED is the process's age; an agent turned a process at 150% CPU with ELAPSED 12 days into "3 cores for 12 days", ~15x too high. *Apply:* before claiming sustained load, divide TIME by ELAPSED, or sample %CPU several times. Report a single reading as "at HH:MM", never as "since". Check the claim before anyone acts on it.
- **Reproduce in the real environment** (2026-07-25). A clean probe can wrongly exonerate a real bug — reproduce through the exact shell/runtime/cache state that exhibits it. *Apply:* 1. Match the runtime CI/production actually uses — check `which -a` and the version through a **login** shell (`zsh -lc`), not the default ssh environment. PATH differs. 2. Defeat caches before trusting a fast result: query names that can't be cached yet. 3. Time individual calls rather than the whole operation, to find the one that holds the delay.
- **Scrubbing half a record launders the same lie** (2026-08-19). Rejecting one field of a geo/lookup record while rendering its siblings as fact launders the same wrong answer through a field nobody re-checked. *Apply:* when a validity check rejects one field, ask what *else* came from the same source in the same call. Drop the siblings that inherit its provenance, or state explicitly why one survives. Keep the case where the sibling arrives *without* the rejected field — that is a different record and usually still good.
- **Sh job notices land in stderr** (2026-10-12). /bin/sh prints "Terminated: 15 ( cmd )" to its stderr when it reaps a killed background job; a wrapper script leaks it into the tool's error. *Apply:* in a wrapper, `exec 3>&2 2>/dev/null` and run the tool with `"$@" 2>&3 3>&- &`, so the shell's own messages go nowhere. `kill $j; wait $j 2>/dev/null` covers only a kill you issue. Force the race in a loop by having the tool kill its sibling first (`pgrep -P $PPID`), which makes the notice certain.
- **Stale swift objects fake a link error** (2026-08-30). Undefined symbols after switching Swift branches is a stale .o against an old mangled name, not a real compile error — delete .build. *Apply:* `rm -rf .build` (or the specific `.build/<arch>/<config>`) and rebuild before spending any time reading the source. Better, avoid it entirely: measure in a *fresh worktree*, which has no `.build` to go stale — that also keeps the tree honest for anything golden-valued, since you cannot be reading a cached artifact from another branch.
- **Swiftui text interpolation groups digits** (2026-10-12). Text("#\\(number)") renders "#2,408" because the literal becomes a LocalizedStringKey; use Text(verbatim:) for ids. *Apply:* use `Text(verbatim:)`, or pass a String variable, for any text that holds an identifier. Keep the interpolating initialiser for prose and for counts meant to be grouped.
- **Tap target hit area verification** (2026-08-15). Two traps that make a hit-area expansion measure correct and do nothing: in-flow paint order, and elementFromPoint being viewport-relative. *Apply:* write the expansion as equal-and-opposite longhands (`paddingTop`/`marginTop`), and prove it with a loop that taps just inside each edge in a real browser, taking the point from `getBoundingClientRect` in viewport coordinates.
- **Validate tickets before building** (2026-07-25). Many tickets are already fixed, or rest on a premise that no longer holds; a local main 799 commits stale nearly sent a "fix" to already-fixed code. *Apply:* `git fetch`, then read the named file or symbol on `origin/main` before building or dispatching. Locate by symbol, not the ticket's line numbers, which drift. If it is already fixed, find the fix commit: one that predates the ticket means the ticket was *wrong*; one that postdates it means the ticket went stale.
- **Viewthatfits reads the unwrapped ideal width** (2026-10-10). SwiftUI ViewThatFits tests each candidate's IDEAL width — a Text's is one unwrapped line — so state the threshold with .frame(idealWidth:maxWidth:) or the wrapping layout is never chosen.
- **Zsh arrays break background watchers** (2026-08-10). Background Bash-tool scripts run under zsh whose arrays are 1-indexed — ${arr[0]} is empty, so array-driven pollers become silent no-ops; use POSIX string ops and dry-run the logic inline before backgrounding. *Apply:* - In any script for the Bash tool (especially long-running background watchers), avoid shell arrays entirely — use POSIX string ops (`head=${remaining%% *}`, `rest=${remaining#"$head"}`) or `set --` positionals, which behave identically in zsh/bash/sh. - Never assign to `status`, `path`, `argv`, or `pipestatus`.
- **Zsh does not split an unquoted variable** (2026-07-27). The Bash tool runs zsh, which does not word-split an unquoted `$VAR`: a built-up flag string passes as one argument and `for f in $FILES` runs once, so a local check can pass while proving nothing, and CI runs bash. *Apply:* run anything CI will run, and any loop over a list, under the shell it targets (`bash -c '...'` or `/bin/bash <<'EOF'`) with a real array (`flags=(a b c); cmd "${flags[@]}"`); in zsh itself, force splitting with `${=VAR}`. Treat "built a flag string in a variable" as a signal to stop and check the shell.
- **Zsh modifiers and builtins in scripts** (2026-10-22). In zsh, "$branch:refs/..." or `git show "$R:apps/..."` applies a history modifier and `log show` runs zsh's log builtin; brace the variable and call /usr/bin/log. *Apply:* write `${branch}` before any `:`, call `/usr/bin/log`, and never `pkill -f` a pattern that appears in your own command line.
