# Lessons

Mistakes already made once, one line each, dated. Read the lines that match your task; delete a line once a check enforces it.

- **A case added after the red run is unverified** (2026-08-30). A case appended to a loop's list after its red run was never shown to fail; verify red per case, not per list. *Apply:* when appending to a table or list of cases a loop or lint runs, re-run the red state and check the failure output names the *new* member. If the fix makes the red state hard to reproduce, pin something that proves the case is still live — a digest of the artefact under test, a count of what it contains — so a case that stops testing anything fails instead of passing.
- **A caught mutant can still be worthless** (2026-09-01). A mutation proves a loop or lint CAN fail, never that what it checks matters — ask whether a user would notice the mutant.
- **A control needs the material that fails** (2026-08-31). A control proves nothing unless its input can exhibit the fault; a determinism check on simple content passed 6 of 6 while the real suite failed 7 of 8. *Apply:* when writing a control, ask what material the fault needs and put that in the control. Where a bug is content-dependent, simplified made-up data is worse than none — it certifies the apparatus while testing the one input that cannot fail. Prefer settling per measurement over a global warm-up: anything that decays with distance from start-up will pass in a quiet process and fail hundreds of renders later.
- **A deadline timeout beside fast neighbours is not contention** (2026-09-01). One step burning the whole deadline while its neighbours run in 30ms means the value never arrives, not that the machine is busy.
- **A differential render check passes on the wrong difference** (2026-08-30). Comparing two rendered states is green whenever anything differs, so a check named for the colour is usually satisfied by the text — or by chrome outside the scroll view. *Apply:* For each render pair, enumerate everything that moves between A and B before believing the result — including chrome you did not think of as content. If more than one thing moves, the drawing cannot isolate the claim: pull the derived value out as a `static` pure function or drop `private`, and have the loop check its answers against recorded ones (`arrow(for: nil) == nil`).
- **A gate on the wrong config passes everything** (2026-09-01). An acceptance gate evaluated under a config the artifact does not ship passes every candidate; the rule then fails on the shipped artifact with nothing red. *Apply:* when a gate takes a config, check the one it *evaluates* is the one that ships, not merely the one that is a parameter. The tell is a gate that never rejects anything. Re-run the rule against the shipped artifact and compare counts — same rule, same gaps, different verdict is the whole diagnosis.
- **A guard needs a fixture the happy path cannot make** (2026-08-30). A guard against an impossible state cannot be tested by a valid flow — the obvious loop passes with the guard deleted, because the input never arose. *Apply:* for any guard, ask what made-up data reaches it and whether a valid flow can build that data. If it cannot, the loop's seed must construct the invalid state deliberately, and its step name says why it looks unreachable. Then **delete the guard and watch the loop go red**.
- **A guard that moves no state needs a side effect assertion** (2026-09-01). A loop for an idempotence guard passes without the guard when the guarded call changes no observable state; check the work it skips. *Apply:* when proving "calling this twice is safe", check the side effect the second call must not have — a task not restarted, a request not re-sent, a value not recomputed — never the state it would not have moved anyway.
- **A killed swift test keeps the build lock** (2026-09-01). A killed swift test orphans a swift-test driver holding .build, and the next run waits on it silently for its whole timeout. *Apply:* when a `swift test` produces no test lines, read the head of its log before blaming load. If the lock line is there, `ps -o pid,ppid,etime,%cpu,command -p <PID>` — PPID 1 with 0% CPU is an orphan, and killing it frees the lock. After killing any test run, check for the orphan rather than assuming the kill was clean.
- **A lower bound can be paid by unrelated latency** (2026-08-31). `elapsed >= expected` is starvation-proof but not bug-proof — any slow thing inside the window satisfies it, including setup you forgot was there. *Apply:* warm up whatever does one-time work (engine, cache, first render) *before* the timed window, and name why in the loop's step. Then mutation-check the check — if forcing the bug still leaves it green, something else is paying the bound.
- **A mutation must build to count** (2026-08-31). A mutation result is meaningless in two ways — it did not compile (looks caught), or it changed no behaviour (looks like a missing check). Check both before counting. *Apply:* the harness must check the loop or suite actually ran — grep its output for a count (the loop's step log, XCTest's `Executed N tests`) and treat its absence as `DID NOT BUILD`, reported separately from both caught and survived. Print applied, built and caught as three numbers.
- **A mutation run must report its own restore** (2026-08-31). A mutation run stopped mid-flight leaves the break in the tree; put the restore inside the script and end with a run whose green proves the tree is back. *Apply:* a mutation run should be one command that cannot end in a mutated state it does not also report. Manual mutate-then-check is what keeps producing these.
- **A negative assertion needs a control** (2026-08-30). Asserting nothing happened is vacuous when the work is async — "it didn't" and "it hasn't yet" are the same observation, and the wrong one passes. *Apply:* whenever a loop checks absence — no sound, no write, no call, no render — ask what would make the observation window provably long enough, and add that as a positive control in the same loop. Treat a bare wall-clock wait before a negative assertion as a defect regardless of whether it is currently passing.
- **A pin must take the input production takes** (2026-08-15). A comment-blindness pin that builds and strips its own string checks the stripper, not the guard: with the strip deleted from the real scan every check stayed green, and an agent who had just diagnosed this defect reproduced it two hours later. *Apply:* route every pin through the real exported predicate, never a re-implementation, and place its made-up input where the unstripped path actually fails (inside the slice the scanner reads, not above it). Then delete the strip and confirm the pin goes red; if it stays green, the input is wrong, not the guard.
- **A pixel count is pinned to the rasteriser** (2026-09-01). A count of differing pixels does not survive a macOS point release; a bounds comparison with a point tolerance does. *Apply:* have the loop compare `differenceBounds(from:)` with a point tolerance, not `differences(from:) > N`. Where a magnitude genuinely is the claim, make it a ratio or a structural fact ("at least a row tall", "at least a third of the region") — never an absolute count. Lowering the threshold buys you until the next OS.
- **A probe must run where the bug lives** (2026-09-01). A standalone probe on an idle machine disproved a race that only happens under load; it could not have reproduced it either way. *Apply:* before a probe retires a hypothesis, ask what it would have printed if the hypothesis were true. If the answer is "the same thing", it is not a disproof, and say so out loud rather than reporting the result as settling it. For an ordering question the deterministic move is to call the two paths in the losing order directly at the layer that owns the state — that turns a race into a defect that reproduces every time, which is what finally fixed it.
- **A push during an opening sheet is lost** (2026-10-22). A screenshot hook's launch-time push while a sheet was still opening was dropped, so the reshot picture showed the wrong screen over a good one. *Apply:* a screenshot hook that pushes or scrolls waits (about 800 ms) until the sheet or form has appeared.
- **A silent timeout blames the wrong code** (2026-08-30). A wait helper that returns whether or not the condition held turns a slow machine into a wrong-value assertion, and the failure message accuses the code under test. *Apply:* make the timeout an outcome — fail the step at the end of the wait, or return a `Bool` the caller must check. Do this *before* considering a longer timeout: lengthening the wait makes a flake rare enough to stop investigating and not rare enough to stop happening.
- **A snapshot cannot assert an order** (2026-08-31). Polling one mutable "last value" for an intermediate state passes or fails on when the poll got a turn; accumulate the sequence instead. *Apply:* make the observation accumulate — record every value with the moment it happened, and derive `last` from the tail so existing callers are unaffected. Then assert on the recorded list, which no amount of starvation can reorder. Widening the gap between events is not the fix: it makes the flake rare enough to stop investigating and not rare enough to stop happening.
- **A straight fixture cannot date a sample** (2026-09-01). A fixture with no curvature makes 'interpolated here' and 'extrapolated back from over there' the same answer — the check pins the geometry and never the moment. *Apply:* when the fix is about *when* or *where* a quantity is sampled rather than how it is computed, ask what property of the made-up data makes the sampling moment observable. Straight lines, constant velocities, symmetric inputs and zero-valued axes all collapse it.
- **A tolerance hides the defect it names** (2026-08-30). An approximate-equality assertion cannot see a defect smaller than its tolerance; where the consequence is discrete, assert the discrete property with no tolerance at all. *Apply:* - Pick a tolerance from the smallest error whose *consequence* matters, and say in the check why that number. If you cannot name the error it must catch, the tolerance is decoration. - Where the consequence is discrete — a threshold crossed, a branch taken, a state entered — assert the discrete property directly, with no tolerance.
- **A total is blind to which member moved** (2026-09-01). "41 of 72 pass" caught 2 of the 5 items that were broken; a population count cannot see a member that moved without crossing the threshold. *Apply:* when per-member data exists, check the named members (`items.filter(\.isFlagged).map(\.name)`), not the cardinality — the diff then says "item-7 left this list". Keep a total only as a cheap extra. Prefer asserting the *rule* over the shipped artifact to asserting a number the rule happened to produce.
- **A verification chain must fail fast** (2026-09-10). A long verification command joined with ; and read through tail -N reports the last step's success while an earlier step silently skipped or failed; twice in one session. *Apply:* do not rely on `set -e` in a Bash-tool command under this harness (zsh): a chain that printed `typecheck errors: 7` and `lint: 2077 errors` still committed and pushed, and a `! grep -q` guard never exits under errexit at all. Write the gate as `[ "$errs" = 0 ] || { echo FAIL; exit 1; }` on its own line, or run the chain as `bash -e script.sh`, and prove the gate once with a deliberately failing input.
- **A wrapper can report success having run nothing** (2026-09-01). A background task reported "completed, exit code 0" for a full test suite whose log was 148 bytes and contained zero test cases — it had only built. *Apply:* never accept a run's verdict from the wrapper's exit code or the harness's completion notice. Open the log and demand a **count** — `Executed [1-9]`, a suite-name roll-call, a passed-test tally — and check the byte size and mtime. A "full suite" log measured in hundreds of bytes ran nothing whatever it exited.
- **An instrument too coarse still returns a number** (2026-08-31). A measurement whose noise exceeds the effect still gives you a figure, and it may have the right sign; and when two careful measurements disagree, the disagreement is the finding. *Apply:* Before trusting a timing, state the effect you expect and the run-to-run spread of the harness; if the spread is the larger, change instrument rather than adding runs. Measure the operation, not the system around it, and interleave arms rather than running them in blocks so drift cannot land on one.
- **Check against the expression not the constant** (2026-09-01). A check pinned to a literal is pinned to the same thing the code is pinned to, so it cannot see them drift apart; check against the canonical expression. *Apply:* where a rule appears in more than one place, derive every copy from the canonical one, or add a lint that they agree. Pin the ends and **not** any point the copies legitimately differ at — one surface legitimately dims the value, and demanding three-way agreement there would assert something the module does not hold, which is a carve-out in reverse.
- **Content and engine can both be right** (2026-08-31). A correct engine plus correct prose still ships a lie when the fixture sits in a different regime from the one the prose describes. *Apply:* for every piece of content that names a physical regime ("past Nyquist", "clipping", "below sensitivity"), run one loop that drives the real engine over that content's own data and checks the regime, not a number. And drive the built artifact once: two panels disagreeing on one screen is a class of bug no unit test is positioned to see.
- **Dont assert from a filtered list** (2026-08-30). I reported fdk-aac as present after a grep that had not matched it; read the output you filtered, don't recall the pattern you filtered with. *Apply:* after a filtering command, name what came back before using it — and when a claim is a list, check each item against the output rather than against the pattern. Where the fact is cheap to test directly (`ffmpeg -encoders | grep X`), test it instead of inferring from a package manifest; a dependency list is not proof a feature was compiled in.
- **Fixture that fails validation tests the error branch** (2026-08-16). Made-up data that fails the component's own validation silently sends every check to the error branch — the happy path never runs, and the run still reads green. *Apply:* when a render path runs input through a Zod (or any) schema, check the *formatted output* in the evidence — the cell reads "Sun 9:00 AM", not merely that a row exists. That check is what makes bad made-up data fail loudly. When adding a fixture for a validated payload, build it from the schema's own field names, and grep the schema rather than inventing a shape.
- **Green ci can still exit nonzero** (2026-08-10). A run reading `Test Files 701 passed / Tests 8333 passed` can still exit non-zero: vitest fails the run on an unhandled error, such as a timer that fires after jsdom teardown. *Apply:* look for vitest's "Errors N errors" line, not a failing assertion. When `gh run view --log` returns nothing, read the job's log through the `jobs/<id>/logs` API.
- **Handoff stated pixel values are derived not measured** (2026-08-15). Design-handoff notes state px measurements they computed from CSS rather than measured; on one project every one was ~4px low. *Apply:* before escalating any ruling premised on a handoff's stated geometry, render the page and measure it.
- **Home screen pwa checks** (2026-10-17). A web app saved to the iPhone Home Screen with `black-translucent` draws white status text over the page, so in light mode the clock vanishes and non-sticky pages scroll under it. *Apply:* use `apple-mobile-web-app-status-bar-style: black`. Emulate the notch headlessly with CDP's `Emulation.setSafeAreaInsetsOverride` (top 59, bottom 34), and sweep every screen for inputs under 16px, cross-origin links without `target=_blank`, a way back, and `scrollWidth > clientWidth`.
- **Huge test arguments hide ci failures** (2026-10-15). Swift Testing prints each parameterized case's argument; a 100,000-tab string cut GitHub's job log short and hid the real failure three times. *Apply:* give parameterized cases with large inputs a short `testDescription`. When a CI log ends without a summary, read the worker log on the runner for the exit code before guessing, and look for giant lines before the cut.
- **Macos fork wedge test stragglers** (2026-09-18). A Go test suite that forks a subprocess thousands of times leaves unkillable stragglers on macOS; check ps before believing a slow or timed-out run. *Apply:* before diagnosing a slow or timed-out local Go suite, run `ps aux | grep '[p]kg.test'` and check the load average. Clear them by the exact PIDs `ps` lists (`kill -9 <pid>`), never a name pattern; a truly wedged one survives even SIGKILL and needs a reboot. Do not conclude a test is flaky or slow until the machine is quiet.
- **Measure the outcome not the proxy** (2026-08-30). A sweep that reads an intermediate state or a derived analogue answers a different question from the one being asked; measure the outcome the user experiences. *Apply:* Before running a sweep, write down the sentence the number has to support ("a request at this load gets through and stays through"). Then check the code reads exactly that, end state included. Where a constant is being set by analogy to an existing one, match the *measured behaviour* of the precedent, not the formula it was derived from — and state the falsification in the doc when the formula loses, because the formula is what the next reader will reach for.
- **Measure through the shipping entry point** (2026-08-30). A harness that fills in one argument the production call derives builds a different population; every number off it is about cases nobody hits. *Apply:* in a harness, call the public entry point callers use and pass only what they pass. If a lower-level builder is genuinely needed, derive every argument the same way the public path does and say so in a comment. When a teammate cannot reproduce a number, diff the *construction* first — same seeds is not the same population.
- **Mutate in a throwaway worktree** (2026-08-30). A mutation run needs a clean tree it owns; in a shared worktree `git checkout --` destroys a teammate's uncommitted work, an auto-commit can ship the mutant, and other agents read code that was never committed. *Apply:* `git worktree add --detach <scratch-path> HEAD`, mutate there, delete it after. Clean by construction, nobody else's edits to destroy, no sidecar, and a kill leaves a dirty tree in a directory that is about to be removed. When someone reports a defect in code you are mutating, check the refs before believing or denying it: `git show <ref>:<path> | grep`.
- **Negative assertions fail open** (2026-07-26). Asserting the ABSENCE of a failure marker is not asserting success — it silently passes the worst outcomes; and pick smoke markers by fetching the real page, not reading the JSX. *Apply:* 1. Assert something only a *working* system produces. "No error shown" is not health. 2. Be suspicious of any check whose passing condition is a `!contains(...)`. 3. When an existing test encodes the buggy behaviour as expected, delete or invert it — don't work around it.
- **Never report an alarm from absence** (2026-09-01). Do not raise an alarm inferred from something being ABSENT from tool output until it is confirmed a second way; truncation looks exactly like deletion. *Apply:* - Absence is the weakest possible evidence. A truncated page, a default `per_page`, a filter typo, a wrong path, and an empty result are indistinguishable from the thing genuinely being gone. Paginate (`--paginate`), widen the filter, or query the specific item by name before concluding it does not exist.
- **Never restore a mutation run from git** (2026-08-31). git checkout -- during a mutation run restores from HEAD or the index, not from your pristine source; cp a copy before the first mutant instead. *Apply:* take a `cp` of each target file before the first mutant and restore from that copy — immune to both. Keep the clean-tree precondition anyway, and always print applied-count alongside caught-count so a non-matching anchor reads as a failure rather than a skip.
- **New gating field flips fixtures to the withheld state** (2026-08-23). A new gating field whose absent case withholds turns every fixture that omits it into the degraded state, and re-recording a snapshot bakes the degraded state in as the baseline. *Apply:* state the new field's value in every fixture's made-up data rather than re-recording; the existing snapshot then passes **unchanged**, which proves the gate leaves an earned screen pixel-identical and removes only what nobody earned.
- **Page clock fakes raf** (2026-10-12). Playwright page.clock (setFixedTime) replaces the PAGE's requestAnimationFrame with a 16ms fake timer — a double-rAF via page.evaluate waits on timers, not drawn frames; use waitForFunction polling:'raf'. *Apply:* count drawn frames with a raf-polled predicate (`page.waitForFunction(fn, arg, { polling: 'raf' })`). A "timed out in the double rAF" failure can be a misattribution: once, two cold `next dev` navigations (44s + 70s) took the 120s budget and the evaluate was merely in flight at teardown.
- **Pin the property not the estates current value** (2026-08-15). A guard or non-vacuity case that hardcodes a design value fails the branch that legitimately changes it, not the branch that breaks the rule; both PRs are green alone, so the clash first shows as a red main. *Apply:* 1. Before pinning a literal in a guard, ask **"is this value someone else's to change?"** Token names, faces, copy, colours, thresholds owned by design — all yes. 2. Derive the case from the same source the guard reads, so it decays with the estate. 3. Give the derived pin a failure message telling the next reader to re-point the case, not delete it — otherwise the first person to hit it buys green by deleting your non-vacuity assertion, and you are back to a guard that passes on nothing.
- **Pipefail grep q guard fails open on a match** (2026-10-10). Under `set -o pipefail`, `if producer | grep -q X; then check; fi` SKIPS the check exactly when X matches a long output (grep -q exits early, the producer dies of SIGPIPE 141, pipefail makes the if false) — it let an ungated PR merge. *Apply:* in any guard script, capture first and compare strings: `files=$(gh pr view "$pr" --json files --jq '.files[].path') || exit 1; case $'\n'"$files" in *$'\n'apps/mobile/*) ...;; esac`. Never `cmd | grep -q` inside an `if` under pipefail; and probe a guard against the case that must REFUSE, not only one that passes.
- **Playwright click waits on the navigation** (2026-10-06). Playwright click()+waitFor() includes the navigation a Server Action redirect triggers: it read a flat ~805 ms where the honest click-to-paint was 695 ms, and stamped an error 100-400 ms after the DOM had it. *Apply:* time UI latency inside the page: stamp `performance.now()` before the click and in a MutationObserver when the target appears. Keep Playwright's own figure only as a sanity check, and treat a flat reading across runs as a reason to distrust the harness first.
- **Playwright screenshot hydration false positive** (2026-06-10). Playwright screenshots default to caret:hide → inject inline caret-color:transparent on inputs; mid-hydration screenshots fake React 'attributes didn't match' hydration errors — screenshot after hydration settles. *Apply:* in verification scripts, take screenshots only after hydration has settled (after a `waitForURL`/network-idle/visible-content wait), or pass `{ caret: "initial" }`; never treat a "hydrated but some attributes" console error as an app failure when an early screenshot was taken.
- **Probe prod before diagnosing scale** (2026-08-04). Twice in one day a diagnosis from code structure alone was wrong: absence of wiring does not imply absence of state. *Apply:* before diagnosing anything about scale, coverage, adoption or "this never runs", spend one read-only query on prod, with least-privilege read-only credentials, run from where the app's environment already lives. Never copy production credentials onto a laptop to do it.
- **Prove the apparatus with identical input** (2026-09-01). When a comparison-based check fails oddly, feed the apparatus identical input before blaming the code — and check it in the configuration it will actually run in. *Apply:* - Before blaming code for a comparison failure, run the comparison on **identical input**. If it reports a difference, the apparatus is the bug. - Report rates, not adjectives: "7 of 8 in release, 0 of 8 alone, 0 of 8 in debug" is reproducible by someone else; "sometimes fails" is dismissed as contention.
- **Ratios get optimised through the denominator** (2026-08-30). Every measurement error in one long session was a ratio whose bottom half was wrong, absent, or shrinkable; prefer denominator-free measures. *Apply:* prefer the denominator-free measure where one exists. Where a ratio is unavoidable: state what it divides by every time it is quoted, charge any search for shrinking it, and validate the proxy against the observable it stands for before optimising it. When two measurements disagree, suspect the denominators before suspecting either measurement.
- **Rendered frames cannot testify to colour** (2026-08-30). Diffing two rendered frames tests geometry honestly but never colour; a sub-pixel move of a neighbour antialiases wide enough to satisfy any size threshold. *Apply:* check positions and extents against the projection or radius rule that produced them, and route colour claims to a screenshot. Where a constant *is* geometric, a linearly-fading gradient is measurable to the pixel — its last ring above 1/255 alpha sits within a point of the stated radius — so pin the exact multiple rather than sandwiching between two bounds; a sandwich passes whichever multiple is used.
- **Scanning guards pass on an empty scan** (2026-08-16). A guard asserting `expect(findings).toEqual([])` passes identically when the estate is clean and when the scan resolves nothing, and a non-vacuity floor that shares the guard's resolver skips along with it. *Apply:* pin one case that MUST report, built from live source rather than made-up data so it decays with the codebase. Then mutate the scanner, never the check: stub the resolver to `[]` or blind the regex, and confirm it goes red. Keep any floor independent of the guard's resolver, loader and skip condition, so one fault cannot silence both.
- **Self comparison tests pin nothing** (2026-08-28). A check comparing a run against another run of itself cannot detect a changed output; only a recorded golden can. *Apply:* Before accepting a green run as evidence that output is unchanged, open the check and see what it compares against. A literal recorded value (a golden, a digest, a hex constant) is a baseline; another invocation of the same code is not. When a green result and a moved number disagree, believe the number and go read the assertion.
- **Shell numeric test on a non number fails open** (2026-10-05). `if [ "$x" -lt "$floor" ]; then refuse` SKIPS the refusal when either side is not a number — the test errors, and an erroring test is false. Write guards as `if ! [ "$x" -ge "$floor" ] 2>/dev/null`. *Apply:* phrase shell guards as "proceed only when the good condition is provably true": `if ! [ "$x" -ge "$floor" ] 2>/dev/null; then refuse; fi`. Then run it with a non-numeric floor and an unreadable measurement, and watch both fail against the `-lt` form.
- **Spawnsync starves an in process test server** (2026-10-06). A child process spawned with spawnSync cannot talk to an http.createServer in the same vitest process — the sync call blocks the event loop, so every request times out and reads as the script under test being broken. *Apply:* when a spawned child must talk back to the test process (a sink server, a mock API), use async `spawn` and `await` the close event; keep `spawnSync` for children that only read files and exit. If a curl against `127.0.0.1` in a test suite exits 28 or prints `000`, suspect the runner before the script.
- **Stopping at a gate floor fails silently** (2026-08-30). A search that stops the moment it clears a threshold banks a result one perturbation from flipping — and if the gate's failure mode is a different valid output, the flip is silent. *Apply:* when a search or tuner has a pass/fail gate, set its stopping rule above the gate with real headroom, and justify the margin from the existing population rather than picking a round number — for example, if the tightest shipping case measures 1.07%, a 1.25% stopping rule has real headroom.
- **Sweeps measure archetypes not physics** (2026-09-01). A bound found by sweeping one configuration is a bound on that configuration; check it against shipped data before it becomes a rule. *Apply:* before a bound goes into code, a doc, or an instruction to someone else, test it against what already ships. Existing artifacts are the only proof that something of that shape *can* exist, since each one already does. Ask what was held fixed during the sweep — that is what the bound is really about.
- **Swift test filter exits zero on no match** (2026-09-01). `swift test --filter` that matches nothing prints a warning and exits 0 — a typo in the filter reads exactly like a passing suite. *Apply:* never accept the exit code alone. Grep the output for `Executed [1-9]` (or count the expected suites) and treat `Executed 0 tests` / `No matching test cases were run` as a failure.
- **Swiftui hit tests the drawing** (2026-08-30). A frame is not a hit target — SwiftUI hit-tests the shape that was drawn, so a circular control is dead in the corners until .contentShape(Rectangle()). *Apply:* only a synthesised click measures a hit region: host the view in an NSHostingView inside a window and send events. Derive the coordinates from the standard's literal (44), never from the constant under test, or shrinking the constant moves the point being clicked instead of failing.
- **Swiftui views need a real window** (2026-10-12). ImageRenderer silently draws nothing inside ScrollView or List and draws AppKit-backed controls as yellow no-entry placeholders, and an offscreen cacheDisplay drops label-coloured text; an NSHostingView in a window lays out for real and accepts synthetic clicks. *Apply:* to picture or click a SwiftUI view on macOS, show it in an NSWindow and capture it with `screencapture -l`, then open the PNG and look before claiming the UI is verified.
- **Test carve outs hide bugs** (2026-11-13). A counter that excuses a category of failure is where the bug will be; audit carve-outs before trusting a green run. *Apply:* when writing or reviewing a loop or lint that counts failures, treat every exception clause as a hole and ask what would prove the excused case is actually correct — then write that assertion separately. When a fuzz run claims to cover "every X", read the generator and list what it cannot produce.
- **Textcontent includes the rsc payload** (2026-08-31). The RSC payload duplicates the page tree, so both textContent and a grep of the built HTML double-count anything you search for. *Apply:* count the tag, not the substring — `grep -o '<script type="application/ld+json"'` — and in the browser use `innerText`. Print line numbers and the surrounding 60 characters rather than a count, so a payload hit identifies itself in one run. A count of exactly double what you expect is the tell.
- **Tokenising a value blinds its numeric guard** (2026-08-15). Replacing a literal with var(--token) silently defeats any regression guard that parsed it as a number — the guard must resolve the token. *Apply:* when a guarded literal becomes a token, fix the *guard*, not the code. Resolve the token and assert on the resolved number, then pin the token itself in a second assertion so re-valuing the scale fails too.
- **Tsc p on a references root checks nothing** (2026-10-17). `tsc --noEmit -p tsconfig.json` on a root with files:[] and references exits 0 having checked nothing. *Apply:* with a references-only root, typecheck each project (`tsc --noEmit -p tsconfig.web.json && …`) or use `tsc -b`. Prove the gate with a deliberate type error before trusting it.
- **Turbo cache hides never run suite** (2026-07-28). A turbo-cached "187 passed" is indistinguishable from a real pass — it can hide a suite that never ran and would fail. *Apply:* when a suite starts failing after a change, do **not** compare against a cached full-suite run. Re-run the *specific file* directly on clean main — `npx vitest run <file> --root apps/<app>` — which bypasses the cache.
- **Vacuous existence guard passes while feature is dead** (2026-08-21). A guard asserting a reference EXISTS proves nothing about whether anything USES it — a slug-parity check passed for months while 1 of 11 categories matched zero records. *Apply:* guarding a mapping between two vocabularies? Assert a non-zero count on the FAR side, not the near side. If the real count only exists in prod, a lint should still check the mapping is non-empty and total, and the prod count gets probed and written down.
- **Verify agent claims against a baseline** (2026-08-07). A correct measurement with no baseline hides regressions; compare against the previous state, not against the spec. *Apply:* For any change to a build, launch, or render path, diff the old and new logs for timings and counts, not just the assertions. Keep prior run logs around for exactly this. Treat a number with no baseline as unverified, however precise it looks. And when the instrument itself is suspect, check it: the same log understated buffer count by a third (reported 54, built 78) because it omitted a newly added array.
- **Vitest 5 under yarn needs an explicit vite** (2026-10-07). Vitest 5 made vite a required peer; Yarn installs no peers, so every Yarn repo's vitest 5 bump dies at startup with "Cannot find package 'vite'" until vite is a direct devDependency. *Apply:* in any Yarn repo taking vitest 5, run `yarn add -D 'vite@^<patched 8.x>'` *before* `yarn up vitest ...`. Doing it after drops vite's subtree from the lockfile and re-resolves `node-gyp@npm:latest` (12.3.0 to 13.1.0 there) for no reason.
- **Vitest globs find agent worktrees** (2026-09-09). Agent worktrees live under .claude/worktrees inside the repo, so vitest's default glob runs their test files against the main tree and reports phantom failures. *Apply:* `exclude: [...configDefaults.exclude, '**/.claude/**']` in `vitest.config.ts`. Check any other repo where agents get worktrees.
