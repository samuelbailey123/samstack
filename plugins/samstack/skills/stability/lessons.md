# Lessons

Mistakes already made once, one line each, dated. Read the lines that match your task; delete a line once a check enforces it.

- **A mac built deploy ships mac binaries** (2026-09-10). vercel build on a Mac bundles only darwin-arm64 native modules (sharp), so a runtime import of one 500s every route that touches it on Linux; keep native deps build-time only or vendor the linux binaries. *Apply:* on a prebuilt-from-Mac project, no native module may load at request time; parse headers by hand or move the work to build time. If one truly must run on Lambda, vendor `@img/sharp-linux-x64` and `@img/sharp-libvips-linux-x64` into node_modules alongside the darwin ones after `npm ci` and add `outputFileTracingIncludes` for them, then assert in CI that the function bundle contains them.
- **A stale override holds the old major** (2026-10-07). An npm override or yarn resolution capped at a consumer's old major silently holds it there after the consumer's major bump, and the alerts keep coming. *Apply:* when clearing alerts or bumping a major, list each override/resolution, then compare it with every consumer's declared range in the lockfile (`packages[*].dependencies[pkg]`). An override narrower than a consumer's own range is a candidate for deletion. Check `git log -S` for why it was added before removing it.
- **Apple profile capability summary lies** (2026-08-09). Apple's portal "Enabled Capabilities" summary omits entitlements the profile actually carries — decode the profile, never read the summary.
- **Colima orphan qcow2 disks after delete** (2026-05-29). colima delete leaves qcow2 disk images on disk — must rm manually to reclaim space.
- **Never dig a name before creating it** (2026-09-10). Querying a Cloudflare-hosted name before its records exist makes Cloudflare's own authoritative edge cache the empty answer for the SOA minimum (30 min); the records then sit in the zone file unanswered. *Apply:* read the API or the zone export to learn what exists; never resolve a name you are about to create. If you already did, expect up to 30 minutes and verify with `dig @<zone NS>` against the SOA TTL rather than reissuing the record.
- **Prisma 7 generate needs a database url** (2026-09-09). prisma.config.ts resolves DATABASE_URL at load, so generate, typecheck-adjacent steps and migrate diff all fail in a fresh worktree; a dummy URL unblocks everything that does not connect. *Apply:* `DATABASE_URL=postgresql://ci:ci@localhost:5432/ci npx prisma generate` for generate/typecheck/tests; source `.env.local` in a subshell (`set -a; source ...; set +a`) only for `db push` and `migrate diff --from-config-datasource`, and only after checking its `DATABASE_URL` is not production. Preview with `migrate diff --script` before any push.
- **Reference vercel cron best effort** (2026-07-27). Vercel cron delivery is best-effort — it silently dropped a scheduled invocation with no log line at all.
- **Tight polling trips the vercel firewall** (2026-08-31). A busy-wait curl loop against a Vercel deploy gets the IP challenged, and every later check returns 403 exactly like deployment protection. *Apply:* put a `sleep 2` in any wait loop against a hosted URL, cap the attempts, and check the deployment's own status with `vercel ls` rather than by polling the page. When a hosted check goes 403 mid-session, read the headers before concluding anything about the project — and verify the build locally with `next start`, which proves the artifact without touching the network.
- **Vercel CLI 53.1.1 — env add silently writes empty values** (2026-05-05). When updating Vercel env vars via CLI, --value and stdin both fail silently — must use REST API directly. *Apply:* When updating Vercel env vars from a script or assistant context, skip the CLI and use the REST API. Seen on 53.1.1 and not retested on later versions: if you try the CLI, read the value back before trusting it.
- **Vercel cost read the bill not request counts** (2026-10-02). Vercel cost triage must start from the usage breakdown ($ per product), never from request counts — 353K crawler requests turned out to be worth $13. *Apply:* for any "our bill is too high" question, open **Vercel → Usage → Consumption Breakdown by product** *first* and rank by dollars. Only then look at Observability request counts, and only to attribute the lines that actually cost money. Note that a single uncached crawler request bills across several lines at once (edge request + function invocation + Fluid CPU + origin transfer + any ISR write), so the fix is usually to remove the expensive *mechanism* rather than to block the traffic.
- **Vercel sensitive vars are placeholders at build** (2026-09-10). With a prebuilt deploy, vercel pull writes the literal "[SENSITIVE]" for every sensitive variable, so anything the build bakes in (CSP, URLs, prerendered queries) gets the placeholder, not the value. *Apply:* at build time trust an env value only if it parses as what it claims to be (an https origin, a postgres URL), otherwise use a committed constant or a fallback path; make prerender reads fail closed to a fallback without caching the failure; and after every deploy that adds an env-driven value, read the live header or HTML for the literal string `SENSITIVE`.
- **Yarn classic cannot copy a dependabot lock** (2026-10-07). Replaying a Dependabot bump with Yarn 1 drifts three ways — caret takes a newer patch, exact drops the caret, transitive ranges stay old — and peers are never installed. *Apply:* when replacing a red Dependabot PR, remove the first failure and run every later CI step. Flag any version drift instead of hiding it. Prove the command list by replaying it on `git archive <base-sha>` and diffing the manifests.
